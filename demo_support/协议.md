# 观测事件来源

GET /events 返回 UTF-8 的 text/event-stream，使用三字节写块，含注释心跳、CRLF/LF、多行 data、错误 JSON 和连续观测 revision。每个正常 data 是原生观测记录；来源和接收时间由订阅配置提供。

Last-Event-ID 原样回送不透明事件标识，来源从该事件开始重发。?cut=4 将响应停在中文字符内部；?conflict=1 让 opaque-a 指向不同观测。GET /requests 可检查收到的续接头。有限响应便于重复演练，客户端可自行按订阅策略重连。

node demo_support/source.mjs --check 执行来源检查。PORT=8787 node demo_support/source.mjs 启动服务。

## FieldLedger 订阅端

订阅入口把上述事件流边接收边送入观测台账，关键约定：

- 事件 ID（opaque-a 等）是不透明传输标识，仅用于 Last-Event-ID 续传与去重；观测记录里的 revision 才是业务版本，两者不能互相替代。
- 接收位置（最后真正落盘的事件 ID）与台账写入在同一个 journal 事务里提交，不会先确认位置再丢掉尚未落库的数据。
- 半个字符/半个事件处断开的连接绝不确认，重连时携带最后一个已完成接收的 Last-Event-ID；服务重发的最后一条按正文摘要幂等去重。
- 同 ID 换正文保留冲突证据（SSE_EVENT_CONFLICT），拒收新正文；坏 JSON 等坏事件保留原文与拒收原因，进入流死信，可单独重新处理，不影响后续正常事件。
- 业务规则拒收（RANGE、REVISION_GAP 等）仍走原有隔离台账，流死信只承载传输/解码/冲突类问题。
- 暂停、恢复、重新配置通过代际（generation）隔离：旧连接积压的回调在代际失效后不能再推进订阅。

node demo_support/stream_demo.mjs 用本地流跑完整演练：半个字符处断开、重发去重、坏事件后跟正常事件、同 ID 冲突留证、慢写入背压，并在重启后对照观测历史与接收位置。
